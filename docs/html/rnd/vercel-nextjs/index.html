R&D 목차로 돌아가기

Vercel + Next.js R&D

이 문서는 WebDrawingCanvas의 server/next-app Next.js 백엔드를 Vercel에 퍼블리싱하는 기준을 정리한다. 목표는 Git push 또는 Vercel CLI로 Preview와 Production 배포를 만들고, Supabase 환경 변수와 API 동작을 안정적으로 검증하는 것이다.

1. 초보자를 위한 한 줄 이해

VercelNext.js 앱을 빌드하고 웹에 공개해 주는 배포 플랫폼이다. Git 저장소와 연결하면 push나 PR마다 자동 배포를 만들 수 있다.
Next.js on VercelVercel은 Next.js를 자동 감지하고 기본 빌드 명령, 출력 경로, 서버 함수 실행 환경을 알아서 설정한다.
Preview 배포운영에 반영하기 전 브랜치나 PR 단위로 만들어지는 테스트 URL이다.
Production 배포사용자가 실제로 접속하는 운영 URL이다. 보통 main 브랜치 merge 또는 vercel deploy --prod로 만든다.
환경 변수Supabase URL, anon key, service role key처럼 코드에 넣지 않는 설정값이다. Vercel은 Local, Preview, Production별로 값을 다르게 둘 수 있다.

2. WebDrawingCanvas 배포 대상

저장소 루트WebDrawing/
Next.js 앱 위치server/next-app/
Vercel Root Directoryserver/next-app로 설정한다. 이 값을 틀리면 루트의 다른 package.json을 기준으로 빌드될 수 있다.
Framework PresetNext.js. Vercel이 자동 감지하지 못하면 수동으로 선택한다.
Build Commandnpm run build. 이 명령은 ../../client를 먼저 빌드해 server/next-app/public으로 복사한 뒤 Next.js를 빌드한다.
Install Command기본 npm install 또는 lockfile 기준 설치를 사용한다.
Output Directory비워둔다. Next.js 배포에서는 Vercel이 산출물을 관리한다. public은 정적 파일 입력 폴더이지 배포 출력 폴더가 아니다.

3. Git 연결 배포 흐름

1단계. GitHub, GitLab, Bitbucket 중 하나에 저장소를 push한다.
2단계. Vercel Dashboard에서 New Project를 만들고 해당 Git 저장소를 선택한다.
3단계. Project Settings에서 Root Directory를 server/next-app로 지정한다.
4단계. Framework Preset이 Next.js인지 확인한다.
5단계. Output Directory가 비어 있는지 확인한다. public을 입력하면 빌드 후 출력 폴더를 찾지 못하는 오류가 날 수 있다.
6단계. Preview와 Production 환경 변수를 등록한다.
7단계. 첫 Deploy를 실행하고 /api/health로 서버가 살아 있는지 확인한다.
8단계. 이후 PR 또는 브랜치 push는 Preview 배포, production branch merge는 Production 배포로 검증한다.
Vercel 공식 문서 기준으로 Git 연결은 브랜치 push마다 Preview 배포를 만들고, production branch에는 Production 배포를 만든다.

4. CLI 배포 흐름

Git 연결 전 빠른 검증이 필요하면 Vercel CLI로도 배포할 수 있다.

cd server/next-app
npm i -g vercel
vercel link
vercel env pull .env.local
npm run build
vercel deploy
vercel deploy --prod
vercel link현재 폴더를 Vercel 프로젝트와 연결한다.
vercel env pullVercel에 등록된 환경 변수를 로컬 .env.local로 가져온다.
vercel deployPreview 배포를 만든다.
vercel deploy --prodProduction 배포를 만든다.
CLI로 배포할 때도 반드시 server/next-app 폴더에서 실행한다. 저장소 루트에서 실행하면 잘못된 앱이 Vercel 프로젝트로 연결될 수 있다.

5. 환경 변수 등록 기준

APP_ENVProduction에는 production, Preview에는 preview 또는 production에 가까운 검증값을 둔다.
DATABASE_PROVIDERVercel에서는 supabase를 사용한다.
NEXT_PUBLIC_SUPABASE_URLSupabase 프로젝트 URL. 브라우저에 노출될 수 있는 공개 설정값이다.
NEXT_PUBLIC_SUPABASE_ANON_KEY브라우저 또는 SSR 클라이언트용 공개 anon key. RLS 정책을 전제로 사용한다.
SUPABASE_SERVICE_ROLE_KEYNext.js API 전용 비밀 키. Vercel Environment Variables에만 저장하고 클라이언트 코드에 노출하지 않는다.
APP_BASE_URLPreview는 Preview URL, Production은 운영 도메인을 사용한다. 공유 링크와 리다이렉트 기준 URL이 된다.
NEXT_PUBLIC_로 시작하는 값은 브라우저 번들에 포함될 수 있다. service role key에는 절대 NEXT_PUBLIC_ 접두어를 붙이지 않는다.

6. Supabase와 함께 배포할 때의 연결 방식

  1. Supabase 프로젝트에 운영 스키마와 RLS 정책을 적용한다.
  2. Vercel Production 환경 변수에 운영 Supabase URL과 키를 등록한다.
  3. Preview 환경은 운영 DB를 그대로 쓸지, 별도 Supabase 프로젝트를 쓸지 결정한다.
  4. 민감한 데이터가 생기면 Preview도 별도 Supabase 프로젝트를 사용하는 편이 안전하다.
  5. 배포 후 /api/health, /api/drawings, 저장/불러오기/삭제 API를 순서대로 확인한다.
이 프로젝트는 10-12에서 Supabase Auth를 연결한 뒤 10-13에서 Vercel Preview/Production 환경에서 인증 세션, DB 연결, Storage 접근 권한을 함께 검증한다.

7. 배포 후 확인 URL

/Next.js 앱 기본 페이지가 뜨는지 확인한다.
/api/health백엔드 API가 정상 응답하는지 확인한다.
/api/drawingsSupabase 연결, 인증 조건, 오류 응답 형식을 확인한다.
Vercel Logs환경 변수 누락, Supabase 연결 실패, 빌드 실패, 런타임 오류를 확인한다.

8. 흔한 실패 원인

Root Directory 오류Vercel이 server/next-app가 아닌 저장소 루트를 빌드하면 Next.js 앱을 찾지 못하거나 다른 명령이 실행된다.
Output Directory 오류Next.js 프로젝트에서 Output Directory를 public으로 지정하면 안 된다. public은 빌드 결과물이 아니라 정적 파일 입력 폴더다.
환경 변수 누락Preview에는 값이 있는데 Production에는 없는 식으로 환경별 등록이 빠질 수 있다.
service role 노출비밀 키에 NEXT_PUBLIC_를 붙이거나 클라이언트 코드에서 import하면 보안 사고가 된다.
Supabase RLS 차단RLS 정책이 너무 엄격하면 API가 빈 목록이나 권한 오류를 반환한다.
Storage 정책 누락DB 저장은 되지만 썸네일이나 업로드 이미지가 보이지 않을 수 있다.

9. 10-13 진행 전 체크리스트

  1. Git 저장소에 최신 커밋이 push되어 있다.
  2. Vercel 프로젝트 Root Directory가 server/next-app로 설정되어 있다.
  3. Framework Preset이 Next.js로 잡혀 있다.
  4. Build Command가 npm run build로 설정되어 있다.
  5. Output Directory가 비어 있다.
  6. Preview와 Production 환경 변수에 Supabase 값이 모두 등록되어 있다.
  7. Supabase 스키마, RLS, Storage bucket과 정책이 적용되어 있다.
  8. Preview 배포 URL에서 /api/health가 성공한다.
  9. Production 배포 전 Preview에서 저장, 목록, 불러오기, 삭제가 동작한다.
  10. Vercel Logs에 환경 변수나 Supabase 연결 오류가 없다.
