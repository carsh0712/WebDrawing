개발 계획서로 돌아가기

기타 단계. Next.js 백엔드, Vercel 배포 및 Supabase DB 연결

대기 React + Vite + TypeScript 프론트엔드 MVP 이후 Next.js 백엔드를 개발하고, Vercel 배포와 Supabase DB/Storage를 연결해 회원, 작업물, 업로드 이미지, 공유 데이터를 저장할 수 있도록 확장하는 개발 계획이다.

1. 목표

프론트엔드 MVP의 로컬 브라우저 저장 구조를 서버 저장 구조로 확장한다. 정식 서비스에서는 회원가입한 모든 유저가 자신의 드로잉 작업물과 업로드 이미지를 계정에 연결해 저장하고 다시 불러올 수 있어야 한다.

배포 환경 Vercel을 사용해 Next.js 백엔드와 웹 앱 배포 환경을 구성한다.
백엔드 환경 Next.js 프레임워크를 사용해 API 라우트, 인증 연동, 서버 저장 로직을 구현한다.
DB 환경 Supabase Database를 사용해 사용자, 프로젝트, 이미지, 공유 메타데이터를 관리한다.
파일 저장 업로드 이미지와 내보낸 결과물은 Supabase Storage 사용을 검토한다.
인증 MVP 이후 회원가입 기반 서비스로 확장할 때 Supabase Auth 사용을 검토한다.

2. 단계별 진행 계획

1단계 Next.js 백엔드 구조 결정: 프론트엔드 Vite 앱과 별도 프로젝트로 둘지, 통합 배포 구조로 전환할지 결정한다.
2단계 Next.js 프로젝트 생성: API 라우트, 서버 전용 Supabase 클라이언트, 환경 변수 로딩 구조를 준비한다.
3단계 Supabase 프로젝트 생성: 개발용 프로젝트를 만들고 Database, Storage, Auth 사용 범위를 정한다.
4단계 환경 변수 설계: Vercel과 로컬 환경에 SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY를 분리 등록한다.
5단계 DB 테이블 설계: 회원, 드로잉 프로젝트, 업로드 이미지, 공유 링크 정보를 저장할 테이블을 설계한다.
6단계 Next.js API 구현: 작업물 저장, 작업물 조회, 이미지 업로드, 이미지 조회 API를 만든다.
7단계 프론트엔드 연결: 기존 Vite 프론트엔드의 로컬 저장 서비스를 Next.js API 호출 방식으로 교체할 수 있게 연결한다.
8단계 인증 확장: Supabase Auth를 연결하고 로그인 사용자 기준으로 작업물과 업로드 이미지 목록을 조회한다.
9단계 Vercel 배포 검증: Preview와 Production 환경에서 환경 변수, DB 연결, 이미지 접근 권한을 확인한다.
10단계 보안 및 권한 검증: Row Level Security, Storage 접근 정책, 공개/비공개 공유 정책을 점검한다.

3. 권장 데이터 구조 초안

3.1 users

idSupabase Auth 사용자 ID와 연결되는 기본 키.
email회원 이메일.
display_name화면 표시 이름.
created_at가입 또는 프로필 생성 시각.

3.2 drawing_projects

id드로잉 작업물 ID.
user_id작업물 소유자 ID.
title작업물 이름.
canvas_width / canvas_height캔버스 크기.
project_data재편집 가능한 작업 데이터 JSON.
thumbnail_url목록 표시용 썸네일 URL.
created_at / updated_at생성 및 수정 시각.

3.3 uploaded_images

id업로드 이미지 ID.
user_id업로드한 사용자 ID.
project_id연결된 드로잉 프로젝트 ID. 독립 업로드를 허용할 경우 비워둘 수 있다.
file_urlSupabase Storage 파일 URL.
file_name원본 파일명.
mime_type이미지 MIME 타입.
created_at업로드 시각.

3.4 share_links

id공유 링크 ID.
project_id공유 대상 작업물 ID.
permission읽기 전용, 복사 가능, 편집 가능 등 권한.
token외부 공유 URL에 사용할 난수 토큰.
expires_at만료 시각. MVP 이후 선택 적용.

4. 환경 변수 계획

SUPABASE_URL Supabase 프로젝트 URL. Vercel 환경 변수에 등록한다.
SUPABASE_ANON_KEY 브라우저 또는 Next.js 클라이언트에서 사용할 공개 anon key. RLS 정책을 전제로 사용한다.
SUPABASE_SERVICE_ROLE_KEY 서버 전용 키. Next.js API 라우트 같은 서버 코드에서만 사용하고 브라우저에는 절대 노출하지 않는다.
APP_BASE_URL 공유 링크 생성과 리다이렉트에 사용할 서비스 기본 URL.
클라이언트에 노출되는 키는 반드시 Supabase Row Level Security와 Storage 정책으로 보호한다. 서버 전용 키는 Next.js 백엔드 환경 변수로만 관리한다.

5. 저장 흐름

  1. 사용자가 로그인한다.
  2. 캔버스 작업을 생성하거나 기존 작업을 불러온다.
  3. Next.js API가 요청을 검증한다.
  4. 작업 중 업로드한 이미지는 Next.js API를 통해 Supabase Storage에 저장한다.
  5. 이미지 URL과 메타데이터는 uploaded_images 테이블에 저장한다.
  6. 캔버스의 재편집 데이터와 썸네일은 Next.js API를 통해 drawing_projects 테이블에 저장한다.
  7. 작업 목록은 사용자 ID 기준으로 조회한다.

6. Vercel 배포 검증 항목

  • Production 배포 URL에서 프론트엔드와 Next.js 백엔드가 정상 로드되는지 확인한다.
  • Vercel 환경 변수 값이 배포 환경에 정상 반영되는지 확인한다.
  • Next.js API에서 Supabase 연결 테스트가 성공하는지 확인한다.
  • DB 읽기/쓰기 권한이 의도한 사용자에게만 열려 있는지 확인한다.
  • Storage 업로드, 다운로드, 썸네일 표시가 정상 동작하는지 확인한다.
  • 배포 후 브라우저 콘솔에 민감한 키나 오류가 노출되지 않는지 확인한다.

7. 완료 기준

  • Vercel 배포 URL에서 WebDrawingCanvas 프론트엔드와 Next.js 백엔드가 정상 실행된다.
  • Next.js API를 통해 Supabase Database에 작업물 메타데이터를 저장하고 조회할 수 있다.
  • Next.js API를 통해 Supabase Storage에 업로드 이미지를 저장하고 다시 볼 수 있다.
  • 로그인 사용자 기준으로 자신의 작업 목록과 업로드 이미지 목록만 조회된다.
  • 환경 변수와 권한 정책이 문서화되어 있다.
