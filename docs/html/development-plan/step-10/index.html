10단계. Next.js 백엔드, Supabase, Vercel 확장

완료 기존 기타 단계의 Vercel 배포, Supabase DB/Storage 연결, 인증, 서버 저장 확장을 10단계 세부 계획으로 통합한다. 현재는 Supabase Auth 연결, Vercel 배포 검증, 보안 및 권한 검증까지 완료했다.

Vercel 배포, 클라이언트 라우팅, CORS, Supabase 권한, 서비스 사용자 설정 중 발생한 실제 오류와 해결 과정은 개발 단계 트러블슈팅에서 시간 순서로 관리한다.

1. 통합 목표

10단계는 프론트엔드 MVP 이후의 전체 백엔드 확장 단계다. React + Vite 클라이언트는 client/에 유지하고, Next.js 백엔드는 server/next-app/에서 독립적으로 개발한다. 개발 환경은 Docker Postgres를 사용하고, 운영 환경은 Supabase Database, Supabase Storage, Vercel 배포를 기준으로 확장한다.

클라이언트client/는 Canvas UI, 로컬 저장, PNG 다운로드 등 브라우저 전용 기능을 담당한다.
백엔드server/next-app/는 API 라우트, 서버 저장, 인증 검증, DB/Storage 접근을 담당한다.
개발 DBDocker Postgres를 사용한다. DATABASE_PROVIDER=docker-postgres와 DATABASE_URL로 연결한다.
운영 DBSupabase Database를 사용한다. 운영에서는 DATABASE_PROVIDER=supabase와 Supabase 키를 사용한다.
파일 저장운영 업로드 이미지와 썸네일은 Supabase Storage 사용을 기준으로 설계한다.

5. 환경 변수 계획

APP_ENVdevelopment, production, test 중 하나를 사용한다.
DATABASE_PROVIDER개발은 docker-postgres, 운영은 supabase를 사용한다.
DATABASE_URL개발 Docker Postgres 접속 문자열. 운영 Supabase 연결에는 사용하지 않는다.
NEXT_PUBLIC_SUPABASE_URLSupabase 프로젝트 URL. 공개 가능한 값이지만 서버 전용 로직은 Next.js API에서만 사용한다.
NEXT_PUBLIC_SUPABASE_ANON_KEY브라우저 또는 Next.js 클라이언트에서 사용할 공개 anon key. RLS 정책을 전제로 사용한다.
SUPABASE_SERVICE_ROLE_KEY서버 전용 키. Next.js API 라우트 같은 서버 코드에서만 사용하고 브라우저에는 절대 노출하지 않는다.
APP_BASE_URL공유 링크 생성과 리다이렉트에 사용할 서비스 기본 URL.
클라이언트에 노출되는 Supabase 키는 반드시 Row Level Security와 Storage 정책으로 보호한다. 서버 전용 키는 Next.js 백엔드 환경 변수로만 관리한다.

6. 완료 기준

  • 개발 환경에서 Docker Postgres를 사용해 작업물 저장, 조회, 수정, 삭제 API가 동작한다.
  • 운영 환경에서 Supabase Database에 작업물 메타데이터를 저장하고 조회할 수 있다.
  • 운영 환경에서 Supabase Storage에 업로드 이미지와 썸네일을 저장하고 다시 볼 수 있다.
  • 로그인 사용자 기준으로 자신의 작업 목록과 업로드 이미지 목록만 조회된다.
  • Vercel Preview와 Production 환경에서 환경 변수, DB 연결, Storage 접근 권한이 검증된다.
  • 클라이언트와 서버 코드 경계가 유지되고, 서버 전용 키가 브라우저 번들에 노출되지 않는다.

7. 10-14 보안 검증 결과

서버 전용 키SUPABASE_SERVICE_ROLE_KEY는 서버 토큰 검증에만 사용하고, 사용자 데이터 접근은 Bearer 토큰 기반 Supabase 클라이언트로 수행하도록 보강했다.
요청자 인증운영 Supabase 모드에서는 Authorization: Bearer 토큰이 없거나 유효하지 않으면 API가 401을 반환한다.
RLS작업물과 업로드 이미지는 요청 사용자 ID로 필터링하고, Supabase 사용자 클라이언트로 RLS 정책을 통과해야 접근된다.
Storage 정책webdrawing-uploads 비공개 버킷과 사용자 ID 폴더 기준 select/insert/update/delete 정책 초안을 docs/backend/supabase-schema.sql에 추가했다.
공유 링크share_links는 연결된 작업물 소유자만 조회, 생성, 수정, 삭제할 수 있도록 정책을 추가했다.
CORSAPI 응답 유틸의 전체 허용 Origin을 제거하고, 미들웨어의 허용 Origin 목록 기준으로 응답하도록 정리했다.
